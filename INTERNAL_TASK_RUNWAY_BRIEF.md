# Decision Archive — Task-first Internal Runway

## First-principles task definition

When a presales or consulting user selects **Freight Audit**, the system should not send them to a Driver description, a Discovery workspace, an Evidence Gate and then an ROI panel. Their immediate job is narrower: prepare the next customer working session with enough structure to make a focused discovery conversation useful.

> **Internal task:** Create a “Freight Audit Exploration Brief” for the next client conversation in under five minutes.

## What the internal user does

The task has three short steps. It does not attempt to create a financial case, assess implementation readiness or enter ROI. Those remain later activities in the Decision Archive.

| Step | Internal user action | Minimum input | Immediate output |
|---|---|---|---|
| **1. Name the situation** | Select the closest live concern. | Invoice errors, duplicate payment, rate variance, or limited audit coverage. | A clear client conversation focus. |
| **2. Choose the evidence to request** | Confirm the smallest useful evidence pack. | Invoices, contracted rates, and payment/dispute trail. | A practical three-item request list. |
| **3. Name the room** | Identify who should attend. | Transport/process owner and AP/finance or data owner. | A 45-minute workshop invite list. |

## What the user gets

After the third step, the interface produces one shareable **Freight Audit Exploration Brief**. It contains the named situation, the three requested inputs, the two roles to invite, and a 45-minute agenda. The user may copy or download it. The brief must state that it prepares Discovery only; it does not estimate ROI or make a product recommendation.

## Product boundary

The full Value Driver Library, Evidence Gate and ROI workspace remain unchanged and accessible as secondary expert tools. They should not appear as forced stages in the first task. The task completion screen may offer one calm secondary action: **“Open detailed Discovery in the Decision Archive.”**

## Expansion pattern

Visibility will later use the same pattern with a visibility/exceptions evidence pack. “Other transport or trade issue” should start by selecting a single driver from the library before a tailored task is created. The first release focuses only on Freight Audit because it is the clearest, most frequent Phase 1 path and avoids pretending that every driver shares identical evidence needs.
